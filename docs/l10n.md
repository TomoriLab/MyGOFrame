# Localization

The native desktop uses the English, Korean, and Japanese catalogs in the repository-root `l10n/` directory. Settings opens **App settings → Language**. App settings also contains translated debug controls and sits immediately above About. The selector applies the chosen language immediately to both native windows through MyGo's locale service. **System language** resumes automatic matching. MyGo persists explicit choices in its user-data `locale` file; for the `mygoframe` executable on Linux this is normally `$XDG_CONFIG_HOME/mygoframe/locale`, with `~/.config` as the default configuration directory.

`MYGO_LOCALE=ko`, `MYGO_LOCALE=en`, or `MYGO_LOCALE=ja` selects a language for one invocation without changing the saved choice. MyGo normalizes regional tags such as `ko_KR.UTF-8` and `ja-JP`. The English source catalog supplies unsupported languages and missing messages. Linux system preferences follow `LANGUAGE`, then `LC_ALL`, `LC_MESSAGES`, and `LANG` as resolved by MyGo 0.8.1.

## Authoring catalogs

Each UTF-8 JSON file uses a canonical BCP 47 language tag as its filename. `@@locale` matches the filename. `@@name` gives the name shown in the language selector, written in that language. All shipped catalogs have the same message keys. Adding another complete catalog with these metadata fields adds the language without editing a Go list.

Static message keys are their English source strings. Presentation calls `text(context, "Start video")`; its English entry is `"Start video": "Start video"`. Translate the value and preserve the key. When changing source wording, update its key in the UI and all catalogs together. Optional ARB metadata such as `@message` descriptions can provide translator context.

Parameterized messages use ICU MessageFormat and named arguments. This permits different argument order and plural grammar:

```json
{
  "License for {name}": "{name} 라이선스"
}
```

Pass arguments through `message(context, pattern, arguments)` or `localization.Format`. Never construct a translated sentence by concatenating a label with dynamic data. Argument data is inserted literally and is not interpreted as another message pattern. `mygo.<key>` entries translate MyGo's native text menus, search controls, and numeric validation.

Keep device names, preset names, paths, codec and pixel-format identifiers, native error details, and authoritative license texts intact. Canonical values such as `Full`, `Off`, `auto`, and `vbr` remain unchanged in session requests and saved presets. `localizedSelect` maps their translated display labels back to their canonical values. Diagnostic CLI help, JSON field names, and enum values remain in English for scripts and troubleshooting. The screen-sharing window retains the stable title `MyGOFrame Capture`.

## Build and verification

`tools/prepare-l10n.py` rejects duplicate keys, empty values, missing metadata, and mismatched message sets. It atomically copies validated resources into ignored `src/internal/desktop/presentation/localization/catalogs_generated/`. The build wrapper performs this step before dependency inventory. Go embeds the resources, so installed binaries need no external translation directory. Debian source builds regenerate the same resources from `l10n/`.

Static translations are cached by MyGo. Unrecognized device metadata and changing diagnostic details bypass that cache. The media transport, frame leases, GPU fences, and Swift session state remain independent of the UI locale.

```sh
make test-l10n
LD_LIBRARY_PATH="$PWD/build" python3 tools/go-mygoframe.py test ./src/internal/desktop/presentation/...
```

The tests parse every ICU message, compare named argument sets, verify English fallback, exercise native text menus and language selection, and preserve canonical capture choices across locale changes. Layout checks cover all three languages at 320×240 through 1920×1080, including app settings, recording controls, presets, and nested license dialogs. Translation tests also check that cached static lookups allocate no memory.
